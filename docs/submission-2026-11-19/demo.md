# 开发版离线演示与评审提问

目标：约8–10分钟展示限定MVP，并让评审看到失败与未验证项。配合[需求表](README.md)及[证据索引](evidence.md)。本次未录制视频；下述为可执行脚本，截图是先前实跑记录。

## 准备

使用现有依赖，从当前仓库启动开发版，避免使用旧release程序。以下启动步骤相当于根`pnpm dev`，直接调用本地工具，不打包或联网下载：

```powershell
Set-Location C:\Users\34381\XDtranC
node packages/main/build.mjs
```

构建退出码0后，在同一PowerShell中启动：

```powershell
node node_modules/electron/cli.js packages/main/dist/main.mjs
```

先把自建`samples/hello`复制到新建的演示目录再导入，避免在仓库样例中留下运行状态。选择的导出父目录和ZIP目标必须是源码目录外的新位置，保留已有文件。CJPM实验选项保持关闭。全程使用Mock；API页面只填假密钥，不启动真实服务转换。

## 操作与预期

| 步骤 / 对应需求 | 演示动作 | 应观察的行为与说明 |
|---|---|---|
| 1 / 范围 | 展示开场与需求表 | “这是C++到仓颉草稿的本地工具；本次证明流程和结构检查，不证明真实模型或编译正确。”指出原功能4/5/6已移出 |
| 2 / R01、R02、R07 | Mock方式，选择样例副本目录，开始转换 | 状态推进；文件树显示输入与chunk归属；可查看源及草稿。说明语法解析和声明摘要不是完整语义分析 |
| 3 / R03、R08 | 检查摘要、问题清单 | 固定Mock样例文件2/2、符号3/3；行保留150%是行数比，不是效果提升150%。说明unsupported、failedChunks、unassigned，不能把缺项隐藏 |
| 4 / R08 | 导出目录与ZIP，各选新目标，读摘要后确认 | 新目录下draft/src与export-manifest.json；ZIP可重读清单。核对simulated=true、providerId=mock、状态、hash、失败项；complete只代表相应流程完成 |
| 5 / R08 | 再选同一个已存在目标导出 | 明确拒绝覆盖，原文件不变；不要为了演示删除原目录 |
| 6 / R10、R11 | 切换OpenAI兼容API，填写`http://127.0.0.1:1/v1`、`offline-demo`、45000与假Key，再提交 | 提交后密码框立即清空，只显示当前地址已配置；提交本身不发模型请求。不点击开始转换 |
| 7 / R10 | 将超时改成1.5，或把地址末尾改成`/chat/completions` | 具体字段提示，开始转换灰显；恢复后格式提示有效不等于网络可用 |
| 8 / R11 | 输入另一段假密码但不提交，切换Mock再返回API；修改base路径；清除密钥；退出重开 | 未提交密码被清空，非敏感参数本页保留；不同地址不可使用旧密钥；清除后无可用Key；重开回到默认Mock、需重新填写与提交 |

## 自动化补充（可在演示前运行）

在同一开发构建上分别执行：

```powershell
node packages/main/cloud-e2e.mjs
node packages/main/workspace-save-e2e.mjs
```

第一项启动本机协议夹具，用假Key验证真正的IPC/按钮链路、外发拒绝零请求、密钥生命周期、重试/取消、错误不回显和导出扫描。原生确认/文件对话框被测试替身替换，不能称为人工外发批准。

第二项通过主进程注入rename占用错误，演示两次失败后恢复、持续6次失败后禁止导出、解除后恢复。它阻断模型fetch，不要求安装真实模型；不代表已复现真实系统文件锁。结果以本次运行输出为准，不把早期截图当成本次新结果。

## 用AI输出做判断的示例

展示API夹具截图：文件2/2、转换结束，但符号覆盖1/3、空壳判定不通过。评审应能解释为何不能只看“完成”。该输出是人工构造的协议夹具，不能说成团队已审阅真实模型草稿。

展示历史eval的`low-retention`：转换和导出complete仍可空壳判定failed；以及`self-check-exhausted`：默认3次后进入失败清单。真实模型输出的人工语义评审记录目前没有，需之后单独补齐。

## 简短口头提问

| 提问 | 应能解释的要点 |
|---|---|
| 为什么engine不能import Electron？ | CLI复用同一服务，不应依赖桌面进程；IPC放在main/preload |
| selfCheck.passed能证明正确吗？ | 不能，是模型自报；schema/路径/覆盖是独立结构检查，语义与编译仍未验证 |
| 为什么改变base路径也不能复用Key？ | Key与规范化完整地址绑定，避免把同一主机上的不同服务混为一体；状态只返回是否配置 |
| Windows保存为什么不删旧文件再重写？ | 保留有效checkpoint；完整临时文件rename替换，特定错误有限重试，失败必须中断 |
| 为什么不自动换到Ollama或Mock？ | 保持用户选定的数据去向与结果性质；失败显式报告，切换由用户决定 |

若评审要求一个小修改，可让团队现场追踪“超时1.5为何被两层拒绝”，或在另行确认范围后修改模型ID长度限制并补边界断言。应由团队说明涉及共享规则、页面、主进程及测试，不预先宣称他们已完成或理解。
