## 3. 架构

```
packages/
├── engine/   纯 Node，禁止 import electron/渲染层；CLI 与主进程共用
├── main/     Electron 主进程 + preload（白名单 IPC）
├── renderer/ React + Vite + 动态 Monaco
├── cli/      复用 engine
└── shared/   contracts.ts / outputSchema.ts（结构化输出唯一真源）
```

- 状态落盘在项目根 `.xdtranc/`：`model/`、`state/<taskId>/task.json`、`events.log.jsonl`、`conversions/`
- 所有写盘必须过路径边界校验；导出目标必须不存在且不与源码双向重叠
- UI 目录导出写 `<目标>\draft\`；CLI `--out` 直接写根目录
- 无数据库、无 HTTP 服务；状态用 JSON + 事件日志
- `contextIsolation: true` / `nodeIntegration: false` / `sandbox: true`，不得回退

## 5. 批次 D 关键实现（新会话最需要知道的）

- `packages/main/src/main.ts`
  - 顶层：`protocol.registerSchemesAsPrivileged([{ scheme: 'app', ... }])`
  - `whenReady` 内：`protocol.handle('app', serveRenderer)`
  - 窗口加载：`await win.loadURL('app://xdtranc/index.html')`
  - `serveRenderer` 只读 `dist/renderer/`，越界返回 403
- `packages/renderer/vite.config.ts`：`root` 为 renderer 目录，`base: './'`，输出 `packages/main/dist/renderer`
- `packages/main/build.mjs`：先 `viteBuild`，再 esbuild，最后 `copyFile` preload
- Monaco：`import * as monaco from 'monaco-editor'`（0.57 的子路径 exports 不同，别再写 `monaco-editor/esm/vs/...`）
- Monaco worker：Vite 8 解析 `?worker` 子路径失败，已改为内联空 `Blob` worker；只读预览够用
- 测试：Vitest 未开 `globals`，RTL 不会自动 cleanup，测试文件必须 `afterEach(cleanup)`

## 8. 硬约束（不可违反）

- 不代跑 git 写操作（add/commit/push/tag/branch/remote/stash）与 `gh`
- 不删除用户数据、不覆盖已存在导出目录、不改内网 ACL、不做外部网络外发

- 每批开始前工作区必须干净；不干净先停下问用户
